# Talk-to-a-Folder

A web app that lets you have AI-powered conversations with the contents of any Google Drive folder. Sign in with Google, paste a Drive folder link, and start asking questions — get answers with citations linking back to source documents.

## How It Works

```
Sign in with Google  →  Paste a Drive folder URL  →  Ask questions  →  Get cited answers
```

A ReAct agent iteratively browses, searches, and reads your Drive files in real time using the Google Drive API, then synthesizes an answer with clickable source citations.

## Architecture

```
React SPA (Vite :5173)  →  FastAPI API (:8000)  →  PostgreSQL
                                  │
                                  ├── Google OAuth 2.0
                                  ├── FolderAgent (ReAct loop, 12 tools)
                                  │     └── Google Drive API (search, read, parse)
                                  └── LLM providers
                                        ├── OpenAI (GPT)
                                        └── Anthropic (Claude)
```

- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS (dark/light theme)
- **Backend**: FastAPI, SQLAlchemy async, Pydantic v2
- **Database**: PostgreSQL (4 tables: users, projects, chat_sessions, messages)
- **Auth**: Google OAuth → encrypted tokens → stateless session cookies
- **LLM**: Model selectable per chat — GPT or Claude via a provider registry pattern
- **Streaming**: SSE for real-time chat responses

## Prerequisites

- **Python 3.12+**
- **Node.js 20+** and npm
- **PostgreSQL** running locally

## Setup

### 1. Create the database

Open your PostgreSQL client (psql, pgAdmin, etc.) and create the database:

```sql
CREATE DATABASE talk_to_folder;
```

### 2. Configure environment variables

Copy the example file and fill in your values:

```bash
cp .env.example .env
```

Edit `.env` with your credentials:

| Variable | Required | What it is |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string. Default: `postgresql+asyncpg://postgres:postgres@localhost:5432/talk_to_folder` |
| `GOOGLE_CLIENT_ID` | Yes | OAuth client ID from [Google Cloud Console](https://console.cloud.google.com/apis/credentials). Create an OAuth 2.0 Client ID (Web application type). |
| `GOOGLE_CLIENT_SECRET` | Yes | OAuth client secret from the same credential above. |
| `GOOGLE_REDIRECT_URI` | Yes | Set to `http://localhost:8000/auth/google/callback` for local dev. Must match the authorized redirect URI in your Google Cloud Console. |
| `OPENAI_API_KEY` | Yes | API key from [OpenAI](https://platform.openai.com/api-keys). Powers the default LLM agent. |
| `ANTHROPIC_API_KEY` | No | API key from [Anthropic](https://console.anthropic.com/). Enables Claude as an alternative model in the chat dropdown. |
| `ENCRYPTION_KEY` | Yes | Fernet key for encrypting OAuth tokens at rest. Auto-generated by the setup script. |
| `FRONTEND_URL` | No | Defaults to `http://localhost:5173`. Only change for production. |
| `AGENT_MODEL` | No | LLM model for the agent. Defaults to `gpt-5.2`. |

> **Google OAuth setup tip**: In Google Cloud Console, enable the **Google Drive API**, create an OAuth consent screen (scopes: `openid`, `email`, `profile`, `drive.readonly`), then create credentials with `http://localhost:8000/auth/google/callback` as an authorized redirect URI.

### 3. Run the setup script

This installs Python/Node dependencies, generates the encryption key, and runs database migrations.

**Windows (PowerShell):**
```powershell
.\setup.ps1
```

**macOS / Linux:**
```bash
chmod +x setup.sh
./setup.sh
```

## Running

**Windows (PowerShell):**
```powershell
.\run.ps1
```

**macOS / Linux:**
```bash
./run.sh
```

This starts both servers:
- **Frontend**: http://localhost:5173
- **Backend**: http://localhost:8000
- **API Docs**: http://localhost:8000/docs

Press `Ctrl+C` to stop both.

## Testing

**Windows (PowerShell):**
```powershell
.\test.ps1
```

**macOS / Linux:**
```bash
./test.sh
```

Runs backend tests (pytest), frontend tests (vitest), TypeScript type checking, and a production build check.

## Deployment

The app deploys as a single Docker image (multi-stage build: Node frontend → Python backend). See `deploy.ps1` / `deploy.sh` for the Azure Container Registry workflow.

```bash
# Build locally
docker build -t tenex .
```
